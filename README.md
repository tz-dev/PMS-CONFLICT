# PMS–CONFLICT

## Purpose

**PMS–CONFLICT** is a paper-form PMS lens for conflict as stabilized incompatibility under binding, time, cost, asymmetry, exposure, and failed integration.

It analyses conflict as a terminal descriptive regime inside a PMS-domain stack. It does not treat conflict as pathology, failure of maturity, moral defect, person type, or automatic demand for mediation.

Compact boundary:

```text
conflict readability ≠ solution
terminal regime ≠ moral verdict
non-integration ≠ pathology
mediation pressure ≠ repair
```

## Core Thesis

Conflict becomes structurally terminal when incompatibility is stabilized across integration pressure, binding, asymmetry, time, and cost such that repair-language itself may become additional conflict load.

Reduced signature:

```text
CONFLICT_terminal_core = Σ + Ψ + Ω + Θ + Χ
```

This marks a descriptive regime, not a solution boundary or final metaphysical claim.

---

## Application Gate

Application use requires:

| Gate | Requirement |
| --- | --- |
| Χ / Distance | Maintained reflective distance; no fusion into verdict, urgency, enforcement, or person-level attribution. |
| Reversibility | Scene-bound and revisable readings; no irreversible actor labels. |
| Dignity-in-Practice | No shaming, ranking, humiliation, or ontological evaluation of persons or groups. |

The gate constrains application. It does not protect PMS from critique.

---

## Terminal Conflict Use

Within this lens, CONFLICT is terminal in a grammar-internal sense.

It may show that:

```text
integration pressure continues
but reintegration is no longer structurally available inside the same frame
```

Continuation beyond that point requires a mode shift into governance, institutionalization, decision, separation, protection, documentation, or another downstream layer.

Terminal does not mean:

```text
absolute end
moral condemnation
no possible external solution
no future change
person-level diagnosis
```

## What the Overlay Adds

`PMS.yaml` supplies the operator grammar. `PMS-CONFLICT.yaml` adds a conflict-specific application profile.

| Added element | Function |
| --- | --- |
| Terminal conflict signature | Reduces recurring conflict configurations to explicit operator patterns. |
| Drift catalogue | Names conflict-specific drift such as Σ-incompatibility clash, binding collision, asymmetry lock-in, exposure capture, and dignity collapse. |
| Non-operator constructs | Provides overlay constructs such as conflict attractor, binding collision, terminal regime, and exposure capture. |
| Scale matrices | Tracks structural projection, publicness, cost, institutionalized Χ, and terminal positioning. |
| Misuse firewall | Prevents conflict readability from becoming sanction, blame, mediation pressure, or person labeling. |

The overlay introduces no new PMS Base operators.

The example suite illustrates conflict as regime rather than defect. The six example families include:

```text
binding without integrability
silence and non-response as load-bearing non-events
forced repair after Σ collapse
moral language as cost obfuscation under exposure asymmetry
mediation that increases conflict load
public alignment that destroys private distance
```

Each example is scene-bound, non-diagnostic, non-prescriptive, and guarded by Χ + reversibility + D.

## Intended Use

PMS–CONFLICT is intended for structural analysis of stabilized incompatibility, not for adjudication.

Permitted use includes:

```text
conflict regime analysis
repair-pressure testing
mediation-risk inspection
publicness and cost analysis
terminal-positioning clarification
research and teaching
```

Prohibited or unsafe use includes:

```text
person labeling
blame assignment
diagnosis
maturity ranking
automatic mediation recommendation
institutional sanction
legal conclusion
```
